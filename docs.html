Documentação da API

Versão actual: mock + localStorage. Ideal para protótipos e pagamentos manuais. Quando tiver backend real, substitua pelos endpoints LIVE.

01 — Conceitos

O fluxo actual é manual:

  • Link de pagamento — gera referência única (PMZ-YYYYMMDD-XXXX)
  • Cliente — transfere via M-Pesa / eMola usando a referência
  • Vendedor — confirma no painel quando recebe o comprovativo
  • Armazenamento — localStorage do browser (não há servidor)

02 — Fluxo recomendado

1. Vendedor cria link → recebe referência + URL pública
2. Partilha a URL ou a referência com o cliente
3. Cliente abre pay.html?ref=PMZ-... e vê instruções
4. Cliente paga e envia comprovativo
5. Vendedor marca como PAID no dashboard.html
6. (Opcional) Vendedor entrega o produto digital

03 — Estrutura de uma transação

{
  "id": "PMZ-20260809-1482",
  "title": "Curso de Vendas",
  "amount": 1500,
  "description": "Acesso completo",
  "sellerPhone": "84XXXXXXX",
  "sellerName": "João Silva",
  "preferredMethod": "any",
  "status": "PENDING" | "PAID" | "CANCELLED",
  "createdAt": "2026-08-09T17:30:00.000Z",
  "paidAt": null
}

04 — Integração futura (quando tiver backend)

Quando migrar para um backend real (Node, Python, etc.), o fluxo pode ser:

POST /api/payments
{
  "reference": "pedido-123",
  "title": "...",
  "amountMzn": 1500,
  "method": "MPESA",
  "payerPhone": "84..."
}

→ Resposta 202 + webhook payment.succeeded

A versão actual do PlayM0z é intencionalmente simples e offline-first. Serve perfeitamente para começar a receber pagamentos manuais enquanto prepara a infraestrutura regulada.
